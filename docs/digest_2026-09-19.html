Claude Code Levels Up: Persistent Cloud Sessions and Smarter Config Discovery

Anthropic has launched a beta of Claude Code Projects, enabling parallel, cloud-hosted coding sessions that keep running even after you close your laptop. In a related update, Claude Code now falls back to reading AGENTS.md when a project lacks a Claude.md file, improving compatibility with existing agent configuration standards.

Why it matters: As an AI Engineer building LLM applications on ServiceNow, these updates directly affect your workflow tooling. Persistent cloud sessions mean you can kick off long-running agentic coding tasks (refactors, migrations, test generation) without babysitting a local machine, which is a big productivity unlock for building AI applications. The AGENTS.md fallback also signals Anthropic is converging toward interoperable agent config standards, which matters if you're integrating Claude Code into multi-tool pipelines or team repos that already use other agent frameworks.

Tiny but Mighty: New Small Models Punch Above Their Weight for On-Device AI

Three separate releases highlight the push toward smaller, more efficient models: Cactus's Needle 3 offers 8-29MB automation models claimed to match DeepSeek V4 Flash performance; Jina AI's jina-ocr-v1 is a 3.4B MoE document parser with built-in speculative decoding designed for low-budget GPUs; and PrismML's Ternary Bonsai 2 27B is a 5.9GB Apache 2.0 licensed model retaining 98.2% of Qwen3.8 27B's performance.

Why it matters: This trio reflects a major trend relevant to your work: shrinking model footprints without sacrificing much capability. For an AI Application Engineer building practical LLM features (e.g., on ServiceNow instances with limited compute, or document-processing pipelines), these releases mean cheaper inference, feasible on-device or edge deployment, and lower infrastructure costs. The permissive licensing (Apache 2.0) also makes Ternary Bonsai a candidate for production use without licensing friction, and jina-ocr-v1's low-GPU-budget design is directly applicable if you're handling document parsing in enterprise workflows.
